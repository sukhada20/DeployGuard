## Proposed Changes

### Postmortem Agent & Report Model

#### [MODIFY] [workflow.py](file:///home/zeph/Code/deployguard/src/deployguard/state/workflow.py)
- Define `PostmortemReport` Pydantic model:
  - `report_id`: Unique UUID/slug (e.g. `pm-{service}-{deployment_id}`).
  - `deployment_id`: Correlated deployment identifier.
  - `service_name`: Name of affected service.
  - `created_at`: Generation timestamp.
  - `target_version`: Injected/failing version.
  - `stable_version`: Target rollback version.
  - `incident_duration_seconds`: Total time from anomaly detection to recovery verification.
  - `severity`: Anomaly severity (`CRITICAL`, `HIGH`, etc.).
  - `outcome`: Final resolution (`recovered`, `failed_rollback`, `policy_blocked`).
  - `executive_summary`: High-level narrative summary of what happened.
  - `root_cause_analysis`: 5-whys structured root cause investigation.
  - `timeline_events`: List of key timestamped milestones (Deployment, Anomaly, Decision, Rollout, Recovery).
  - `metric_deltas`: Baseline vs peak anomalous values across 7 dimensions.
  - `decision_summary`: Governed action rationale, confidence, and policy check results.
  - `rollback_summary`: Cloud Deploy operation ID, rollout target, and execution status.
  - `preventative_actions`: List of actionable engineering recommendations.
  - `trace_id`: OpenTelemetry trace ID for deep linking.
  - `.to_markdown()`: Generates clean, publication-ready SRE Markdown document.
  - `.to_dict()`: Serializes structured document for JSON persistence and API payloads.
- Update `DeploymentWorkflowState` to include `postmortem_report: Optional[PostmortemReport] = None`.

#### [MODIFY] [postmortem.py](file:///home/zeph/Code/deployguard/src/deployguard/agents/postmortem.py)
- Refactor `PostmortemAgent._execute()` from stub to complete production workflow:
  1. Retrieve `DeploymentWorkflowState` from `ctx.session.state`.
  2. Assemble deterministic facts: timeline milestones from state history, metric delta table from `state.anomaly_signal`, policy results from `state.decision_trace`, and rollback outcome from `state.recovery_verdict`.
  3. Narrative generation (D-01, D-03):
     - If `DEPLOYGUARD_MOCK_GCP=false` and Gemini client available: Invoke Gemini 2.5 Flash with structured prompt and Model Armor sanitization to synthesize `executive_summary`, `root_cause_analysis`, and `preventative_actions`.
     - If in mock mode (`DEPLOYGUARD_MOCK_GCP=true`) or Gemini API call errors/times out: Use deterministic template generator to populate narrative sections gracefully without failing the agent execution.
  4. Construct `PostmortemReport` instance and attach to `state.postmortem_report`.
  5. Persist report to Firestore collection `postmortems` using `FirestoreClient` / `FirestoreStub`.
  6. Yield ADK `Event` containing report ID, outcome, and Markdown preview.

#### [MODIFY] [stubs.py](file:///home/zeph/Code/deployguard/src/deployguard/cloud/stubs.py) & [interfaces.py](file:///home/zeph/Code/deployguard/src/deployguard/cloud/interfaces.py)
