# Plan 05-03 — OpenTelemetry Distributed Tracing & GCP Exporter

**Phase**: 05 — Rollback Execution & Recovery Verification
**Plan**: 05-03
**Wave**: 3
**Depends on**: 05-01, 05-02
**Objective**: Implement OpenTelemetry distributed tracing across the deployment lifecycle with dual exporter configuration (Cloud Trace vs InMemory), unified root-to-child span hierarchy, and W3C TraceContext propagation.

## Proposed Changes

### OpenTelemetry Telemetry Module

#### [NEW] [tracer.py](file:///home/zeph/Code/deployguard/src/deployguard/telemetry/tracer.py)
- Create telemetry package `src/deployguard/telemetry/`.
- Implement `init_tracer()` configuring `TracerProvider` with dual exporter (D-05):
  - When `DEPLOYGUARD_MOCK_GCP=true` (or in test environment): Use `InMemorySpanExporter` / `ConsoleSpanExporter`.
  - When `DEPLOYGUARD_MOCK_GCP=false`: Use `CloudTraceSpanExporter` from `opentelemetry.exporter.gcp_trace`.
- Implement span context manager helpers for agent lifecycle stages (D-06):
  - Root span: `deployguard.deployment` (attributes: `deployment_id`, `service_name`, `environment`, `version`).
  - Child spans:
    - `deployguard.monitor.detect` (attributes: `severity`, `affected_metrics`)
    - `deployguard.decision.evaluate` (attributes: `decision`, `confidence`, `policy_passed`)
    - `deployguard.rollback.execute` (attributes: `target_version`, `operation_id`)
    - `deployguard.monitor.verify_recovery` (attributes: `verdict`, `recovery_checked_at`)
- Implement W3C TraceContext injection into and extraction from ADK session state (`ctx.session.state["trace_context"]`) and log correlation.

#### [MODIFY] [base.py](file:///home/zeph/Code/deployguard/src/deployguard/agents/base.py)
- Integrate tracer span context into `BaseDeployGuardAgent` invocation lifecycle.
