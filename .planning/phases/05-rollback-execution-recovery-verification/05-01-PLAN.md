## Proposed Changes

### Rollback Agent & Cloud Deploy

#### [MODIFY] [rollback.py](file:///home/zeph/Code/deployguard/src/deployguard/agents/rollback.py)
- Refactor `RollbackAgent._execute()` from stub to full execution workflow:
  1. Retrieve `DeploymentWorkflowState` from ADK `ctx.session.state`.
  2. Perform two-tier security check (D-07):
     - Verify calling identity via `AgentRegistry` and `@gateway_tool`.
     - Check `state.decision_trace`: ensure `decision == "rollback"`, `policy_passed is True`, and `authorized is True`.
  3. If check fails or trace is missing (ROLL-03):
     - Set `state.rollback_authorized = False` and `state.rollback_executed = False`.
     - Set `state.pipeline_status = "failed"`.
     - Log security denial / policy refusal and yield informative `Event`.
  4. If check passes:
     - Set `state.rollback_authorized = True`.
     - Resolve stable release ID using convention (D-01): `release-{service_name}-{stable_version}` (dots replaced by hyphens). If stable version is missing, fail execution.
     - Call Cloud Deploy client (`LiveCloudDeployClient` or `MockCloudDeploy`) `execute_rollback()`.
     - Poll rollout status until terminal state (`SUCCEEDED` / `FAILED`) with configurable timeout (D-02).
     - On successful rollout, update `state.rollback_executed = True`, `state.rollback_target_version = stable_version`, `state.rollback_operation_id = op_id`, and `state.pipeline_status = "verifying_recovery"`.
     - Yield `Event` confirming rollback completion.
